# 픽업메이트 탑승자 앱

Flutter Android·iOS 앱과 Go 기반 로컬 시연 서버입니다. 현재 구현은 **개발용 프로토타입**이며 실제 탑승자 계정 인증, 요청 알림, 운영용 개인정보 저장소가 없습니다. 실사용자의 연락처, 위치, 메시지 대신 테스트 데이터만 사용하세요.

## 구성

- `app/`: Flutter 탑승자 앱
- `server/`: Go 로컬 시연 API. 차량 앱의 기존 픽업 API 형식과 호환되도록 구현
- 차량 앱: 별도 저장소 `pickup-mate-lab/Pickup`

## 로컬 시연 시작

1. 기존 Python 데모 서버를 쓰고 있다면 종료해 포트 8787을 비웁니다. 두 서버는 데이터가 공유되지 않으며 서버를 종료하면 시연 세션이 사라집니다.
2. PowerShell에서 Go 서버를 실행합니다.

```powershell
cd C:\Users\gimse\PickupPassenger\server
$env:PICKUP_DEMO = '1'
go run .
```

서버는 기본적으로 `127.0.0.1:8787`에서만 대기합니다. `PICKUP_DEMO=1`은 인증되지 않은 로컬 테스트 요청 연결 기능을 켜므로 운영 환경에서 사용하면 안 됩니다. 서버는 데모 모드에서 외부 인터페이스 바인딩을 거부합니다.

3. Android Studio에서 `C:\Users\gimse\PickupPassenger\app`을 열고 **일반 Android 휴대전화 에뮬레이터**를 선택해 실행합니다. CLI에서는 다음과 같습니다.

```powershell
cd C:\Users\gimse\PickupPassenger\app
flutter pub get
flutter run
```

4. 앱에서 **데모 요청 확인**을 누릅니다. 같은 Go 서버에서 차량 앱이 미리 생성한 대기 요청이 있다면 그 요청을 시연용으로 열고, 없으면 별도 데모 요청을 생성합니다. 실제 연락처 기반 사용자 인증이나 요청 전달이 아닙니다.
5. 지도를 눌러 승차 지점을 선택하고 이름을 적은 뒤 **요청 수락하고 승차 지점 전달**을 누릅니다. 차량 앱도 같은 Go 서버를 사용 중이면 기존 NaviHelper 흐름으로 지점 변경을 확인할 수 있습니다. 탑승자 앱에서는 이후 지점 변경과 텍스트 메시지 전송을 시험할 수 있습니다.

Android 에뮬레이터의 `10.0.2.2:8787`은 PC의 `127.0.0.1:8787`로 연결됩니다. 로컬 HTTP 예외는 Android 디버그 빌드에서만 허용하며 임의 원격 주소에는 사용하지 않습니다. 지도 타일에는 인터넷이 필요하고 OpenStreetMap 데이터 출처가 표시됩니다.

## 위치 공유와 종료

- 지도에서 지점을 고르는 것과 실시간 현재 위치 공유는 별도입니다. **내 현재 위치 공유**를 직접 켜고 기기 권한을 허용한 경우에만 앱이 열린 동안 위치를 전송합니다.
- 앱이 비활성화되거나 픽업이 끝나면 공유 중단을 요청합니다. 통신이 끊겨 중단 요청을 전달하지 못한 경우에도 서버 접근 시 45초 이상 오래된 탑승자 위치를 삭제합니다. 이는 운영용 위치 보호 시스템을 대체하지 않습니다.
- 시연 요청은 메모리에만 저장하며 2시간 후 만료됩니다. 서버에 접근할 때 만료 상태를 확인하고 위치·메시지를 지웁니다.
- 운전자 예상 도착 시간이 서버에서 제공되지 않으면 앱은 임의의 시간을 계산하지 않습니다.

## 아직 구현하지 않은 기능

- 연락처/전화번호 기반 실사용자 인증, 안전한 운전자·탑승자 연결과 요청 푸시 알림
- 백그라운드 위치 공유, 도착 전 푸시 알림, 도보 이동 시간 예측
- 탑승자 음성 메시지 입출력 및 실제 iPhone 빌드 검증
- 운영용 서버 인증·HTTPS·데이터베이스·접근 제어·안전한 저장/삭제

Windows에서는 Android를 개발·빌드할 수 있습니다. iOS 빌드·시뮬레이터와 실제 iPhone 테스트에는 macOS, Xcode 및 서명 설정이 필요합니다. iOS에서는 HTTPS 서버를 설정해야 합니다. 기본 `10.0.2.2` 주소는 Android 에뮬레이터 전용입니다.
