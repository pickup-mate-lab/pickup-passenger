# 서버 실행 준비

> 아직 어떤 서버에도 배포하지 않았습니다. 테스트용 구성입니다.

## 필요한 것

- Docker Engine과 Compose가 설치된 Linux 서버 한 대 및 서버를 가리키는 도메인
- 서버로 향하는 TCP 80·443 포트. Caddy가 HTTPS 인증서를 자동 발급합니다.
- Firebase 프로젝트 ID와 Firebase Admin 서비스 계정 JSON 파일(비밀키). JSON 파일은 저장소 바깥의 접근 제한된 위치에 보관하고, 컨테이너의 `pickup` 계정이 읽을 수 있어야 합니다.
- 선택 사항: TMAP 보행자 경로 API 앱 키. 없으면 도보 출발 시점 계산이 비활성화됩니다.

## 설정과 실행

1. `deploy/.env.example`을 복사해 `deploy/.env`를 만들고 `PICKUP_DOMAIN`, `FIREBASE_PROJECT_ID`, `FIREBASE_CREDENTIALS_PATH`, `TMAP_APP_KEY`를 설정합니다. `.env`와 서비스 계정 키는 커밋하지 않습니다.
2. 서버 프로젝트의 `deploy` 폴더에서 `docker compose config --quiet`로 설정을 확인합니다.
3. `docker compose up -d --build`로 실행합니다. `docker compose ps`와 `docker compose logs --tail=100`으로 상태를 확인합니다.
4. `https://도메인/health`가 `{"status":"ok"}`를 반환하는지 확인합니다. 앱 빌드의 서버 주소는 이 HTTPS 도메인으로 지정합니다.

Go 서버는 컨테이너 내부 `127.0.0.1:8787`에서만 수신합니다. Caddy는 서버와 네트워크 네임스페이스를 공유하며 80·443 포트만 외부에 공개합니다. 데모 모드를 켜지 않습니다.

## 운영 전 확인

- 서버와 Caddy의 데이터 볼륨을 안전하게 백업하고 저장 장치 암호화 및 접근 제한을 적용합니다. bbolt 데이터는 애플리케이션 차원에서 암호화되지 않습니다.
- 현재 bbolt는 단일 서버 인스턴스만 지원합니다. 여러 복제본에서 동일 파일을 공유하거나 무중단 확장하는 구성은 지원하지 않습니다.
- 앱에서 픽업 요청, SMS 인증, 위치 공유 종료, 메시지, 도착 및 출발 알림을 실제 기기에서 확인합니다. iOS는 APNs와 Xcode 설정 및 Mac 빌드가 필요합니다.
- 큐는 전달 성공 확인 전에 서버가 재시작되면 같은 알림이 중복될 수 있습니다. 푸시 수신은 통신망 및 기기 설정에 따라 보장되지 않습니다.
- 알림은 최대 15분 동안 재시도하며, 완료·만료된 픽업과 이전 승차 지점의 알림은 버립니다. 요청, 메시지, 도착·출발 알림은 해당 픽업 상태와 함께 저장합니다. 도착 관련 알림은 재시작 이후 새 차량 도착 시간이 들어올 때까지 전송을 기다립니다.
